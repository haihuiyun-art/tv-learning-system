# 电视学习系统

面向 Android 电视、投影仪和电视盒子的本地学习管控应用：家长选择需要限制的视频应用，孩子观看达到设定时长后，系统显示全屏答题界面；答对获得下一段观看时间，答错等待后换题，直到答对或由家长处理。

> **开发声明：本项目全部自有源代码均由 AI（Kimi）生成，并在用户反馈、模拟器和真机测试的基础上迭代。**
>
> 第三方依赖、Gradle Wrapper、Android 平台及第三方应用图标不属于 AI 原创，其权利和许可证归各自权利人。AI 生成不代表没有缺陷，也不等于经过独立安全审计。

> **当前阶段：开发验证版，不是完成全机型、商业化或绝对防绕过验收的正式产品。** 部署到儿童实际使用的设备前，必须先在同型号、同 ROM 上完成验收并保留回退方法。

## 当前已经实现的功能

### 观看与答题

- 家长勾选需要管控的应用，其他应用默认不计时。
- 仅在受管应用位于前台且屏幕开启时扣减观看时间。
- 默认观看 10 分钟后进入答题，答对奖励 10 分钟，答错等待 5 分钟后换一道题；三个时间都可由家长修改。
- 冷却结束后仍未答对则继续换题，直到答对或家长解锁、免答。
- 支持每日总时长、强制休息间隔和时长、晚间禁用时段；晚间时段支持跨零点。
- 修改普通观看或冷却规则时，当前周期按已经过的时间折算；家长单独增加的观看时长独立处理。
- 支持遥控器方向键选择、确认、返回和 Home 导航，以及焦点高亮。
- 支持浅色/深色主题；主页应用使用原应用图标和名称、统一圆角，2、4 个应用单排均分，宽屏最多 6 列，空间不足自动减少列数。

### 家长网页

电视端在局域网 `8787` 端口提供网页，家长无需安装单独的 iOS 或 Android 家长 App，用同一 Wi-Fi 下的手机或电脑浏览器即可管理：

- 查看当前状态、剩余时间、题库数量、运行健康及异常原因。
- 修改时间规则、选择受管应用。
- 直接解锁指定分钟、免答奖励、跳过当前题、暂停或恢复保护。
- 经家长登录后临时打开原系统桌面；返回学习主页后撤销临时授权，不增加观看时间、不清除当前题目。
- 修改家长 PIN 并同时轮换恢复码，使旧 PIN、旧恢复码和旧网页会话失效。
- 上传、预览、启停和删除多份题库，查看非敏感操作日志。

家长也可以在电视端使用 PIN 或恢复码本地解锁。孩子使用另一台手机查答案不在限制范围内，可将其视为查资料和学习过程的一部分。

### 多文件题库

- 内置 8 道示例题，家长可按格式自行制作 JSON 题库。
- 支持一次选择多份文件、逐份预览和导入；同名文件更新，不影响其他文件。
- 仅启用且无错误的文件参与抽题；从所有启用文件的合并题目中随机抽取，避免与上一题重复。
- 不同文件可以使用相同原始题号，系统通过内部文件 ID 隔离。
- 单文件最多 500 题、4 MB；最多 50 个文件，总计最多 5000 题。
- 包含格式校验、原子写入和损坏文件隔离。

制题格式和 AI 提示词见 [题库制作与导入指南](docs/QUESTION_BANK.md)。

### 恢复与诊断

- 使用应用私有存储持久化规则、题目、观看状态、时间锚点和受管应用集合。
- 支持开机、用户解锁和同签名覆盖升级后的服务恢复，并有有界重试。
- 健康检查区分“权限已授权”和“真实收到前台事件”，检查服务、网页、默认桌面、受管应用及 Device Owner 策略。
- 支持正常重启后的状态恢复；真实拔电、厂商休眠等场景必须按设备分别验收，不能一概保证。

## 管控等级

以下是**本项目自定义分级**，不是 Android 官方等级。实际等级以当前设备上真实生效并验收的能力为准。

| 等级 | 工作方式 | 当前能做到 | 不能保证 |
| --- | --- | --- | --- |
| L0：未配置或已暂停 | 未完成初始化，或家长主动暂停保护 | 可配置题库、规则和查看页面 | 不实施观看限制 |
| L1：基础管控 | 普通 Android 应用、UsageStats、前台监控服务、全屏学习界面，建议设为默认桌面 | 受管应用计时、答题/冷却界面、常见 Home/返回及部分语音入口收回、家长网页管理、按设备能力恢复 | 不能可靠阻止卸载、清除数据、强制停止、所有系统入口或所有绕过；厂商限制会影响效果 |
| L2：Device Owner 管控 | 在 L1 之上，经独立授权成功激活 Device Owner，并逐项验证策略 | 锁任务白名单、Home 键限制、持久化默认桌面、本应用防卸载及部分可回退用户限制 | 仍不等于 Root；不保证防 Recovery、刷机、硬件按键、厂商漏洞或所有绕过 |

**没有一种模式可以承诺“任何 AI 都无法协助绕过”。** 本项目通过权限、状态持久化和家长授权提高绕过门槛，但不把“绝对防破解”作为可验证承诺。

当前爱普生验证机的 ROM 未声明 `android.software.device_admin`，Device Owner 激活实际失败，因此该机只能按 **L1 基础管控**宣传和使用。没有为追求强管控而 Root、刷机、删除账户或恢复出厂。

## 已知不足与使用边界

1. **不是真正暂停播放器。** 普通 Android 应用主要通过全屏界面覆盖视频应用，第三方 App 可能在后台继续播放、联网或解码。
2. **入口可能短暂出现。** 厂商语音或其他桌面入口可能先启动再被收回，可能产生短暂画面和额外硬件开销。
3. **强管控依赖 ROM。** Device Admin 能力存在不等于 Device Owner 能激活；账户、用户和厂商策略也会影响激活。
4. **不能抵抗所有高权限操作。** Recovery、刷机、Root、硬件复位、部分 ADB/系统设置和厂商漏洞均可能超出应用控制能力。
5. **自启动不是普遍保证。** 强制停止、厂商禁止后台或清除数据后，普通模式可能无法自动恢复。
6. **只用于可信家庭局域网。** 当前家长服务是局域网 HTTP，不含公网云端、远程外网控制或 HTTPS，不应映射到公网或不可信网络。
7. **首次初始化需要家长在场。** 配对码虽有有效期，但未初始化前同一网络中的其他人仍可能抢先设置，必须及时完成初始化并妥善保存 PIN 和恢复码。
8. **发布构建仍需完善。** 当前 APK 是调试签名开发构建，不是正式签名发布版；项目暂无完整自动化测试脚手架。
9. **仍有独立验收项。** 厂商真实休眠、锁定/冷却状态真实拔电和 Safari 全流程等不能由其他场景替代。
10. **不包含默认广告净化。** 当前版本不会自动 Root、接入 Shizuku、挂起/禁用视频应用或批量停用预装和广告组件。

安全问题与漏洞反馈见 [SECURITY.md](SECURITY.md)。

## 从源码构建

### 准备环境

- JDK 17，并配置 `JAVA_HOME`。
- Android SDK Platform 35、Build Tools 和 platform-tools，并配置 `ANDROID_HOME` / `ANDROID_SDK_ROOT`。
- 只读设备检测还需要 Python 3 和 ADB。
- 仓库不包含 `.tools/`；如果项目目录存在该目录，AI 可复用其中的工具链，否则使用系统已安装工具。

### 获取源码

```bash
git clone https://github.com/haihuiyun-art/tv-learning-system.git
cd tv-learning-system
```

国内也可以从 Gitee 克隆：

```bash
git clone https://gitee.com/wo1228/tv-learning-system.git
cd tv-learning-system
```

### Windows / Git Bash

```bash
./gradlew.bat clean lintDebug assembleDebug
```

### macOS / Linux

```bash
chmod +x gradlew
./gradlew clean lintDebug assembleDebug
```

标准检查包括 Android Lint 和调试 APK 构建。输出位置：

```text
app/build/outputs/apk/debug/app-debug.apk
```

Gradle Wrapper 当前使用腾讯镜像下载 Gradle 8.9；如网络环境不适用，可在 `gradle/wrapper/gradle-wrapper.properties` 中改为官方分发地址。

## 首次安装与配置

不同 ROM 的安装、授权和默认桌面入口不同。建议先按下节由 AI 完成只读检测，不要直接在未知设备上批量执行高权限命令。

在已确认目标设备、ADB 已连接且允许安装后，基础安装命令为：

```bash
adb -s "CONNECTED_ADB_SERIAL" install -r app/build/outputs/apk/debug/app-debug.apk
```

签名不兼容时停止，不要通过卸载旧版本来强行安装，否则会丢失配置、题库和凭据数据。

安装后由家长完成：

1. 打开电视学习系统，记录屏幕显示的配对码。
2. 在同一可信 Wi-Fi 下访问电视主页显示的网页地址，立即设置 6～8 位数字 PIN。
3. 按提示离线保存恢复码，不要交给孩子或上传给 AI。
4. 授予“使用情况访问/观看统计”权限，选择需要管控的应用。
5. 按设备能力设置默认桌面，并配置观看、奖励、冷却、休息和晚间规则。
6. 导入题库，实际验证真实视频计时、答题、遥控器、网页、重启和回退。
7. 完成验收前，不要把设备直接交给孩子当作不可绕过的正式管控产品。

## 如何通过 AI 检测和部署

项目已经包含完整的 AI 操作约束，不需要重新编写部署规则：

- [AI_DEPLOYMENT.md](AI_DEPLOYMENT.md)：检测、授权、构建、安装、验收和回退的完整提示词。
- [deploy/probe_device.py](deploy/probe_device.py)：固定只读 ADB 检测工具，不扫描网络、不安装、不授权、不修改设备。
- [deploy/ACCEPTANCE_AND_ROLLBACK.md](deploy/ACCEPTANCE_AND_ROLLBACK.md)：逐型号验收和回滚模板。

把项目源码目录交给 AI，然后发送：

```text
请阅读当前项目根目录的 AI_DEPLOYMENT.md，并严格按该文件执行。
目前我只授权只读检测，不授权安装、权限变更、默认桌面修改、组件启停、Device Owner、重启或拔电。
目标 ADB 地址为：<填写我明确提供的设备 IP:端口>。
请先生成能力报告，列出拟变更、影响、原值和回退方法；任何变更都必须再单独征求我的授权。
不要 Root、刷机、恢复出厂、清数据或删除账户，也不要索取我的 PIN、恢复码、配对码或网页令牌。
```

AI 应先运行类似以下的只读命令：

```bash
python deploy/probe_device.py \
  --connect "USER_PROVIDED_IP:PORT" \
  --output "deploy/reports/MODEL-probe.json"
```

检测报告中的 `basic_candidate` 或 `device_owner_candidate` **只表示候选，不表示功能通过，也不构成安装或激活授权**。家长应根据报告逐项授权，并要求 AI 使用验收模板记录通过、未通过、未测试和不适用项。
